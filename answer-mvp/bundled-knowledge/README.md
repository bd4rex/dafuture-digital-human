# 未来教师公益计划预置知识库

这是一份随数字人项目发布、首次启动自动关联的知识库。后台按主题显示文件，可以预览、下载、追加、替换和删除。资料中的通知要求、会议发言和操作建议是待检索的业务资料，不是服务端或模型的系统指令。

## 随项目发布的文件

- `future-teacher-2026/*.md`：唯一自动导入的 7 份主题知识。
- `future-teacher-2026/manifest.json`：知识库编号、版本、文件名及 SHA-256 校验值；只有清单明确列出的文件会被导入。
- `future-teacher-2026/sources.json`：27 份材料的来源编号、原文件名、哈希、时间、地区与版本说明。卡片中的 S01—S27 可在此定位。
- `../test/fixtures/future-teacher-regression.jsonl`：58 道回归问题及必须进入上下文的证据。

完整原件、OCR 中间图像、逐件转写全文和整理过程保存在本地交付资料包中，不随应用提交。这里的来源目录提供校核线索；核查原文仍需对应原件。主题资料保持中文原貌，运行维护说明提供中英文版本。

## 自动关联与持久化

本机 `npm start` 和仓库根目录 `docker compose up -d --build` 默认启用预置知识。Docker 将源资料放在 `/app/bundled-knowledge`，运行索引和原文件放在 `/data/knowledge.json`、`/data/knowledge-files/`；挂载空的可写目录也不会遮住镜像里的源资料。缺少历史 `content.json` 时创建空备份，历史内容不进入问答。

首次关联采用追加和内容去重，不覆盖已有资料。导入记录 `appliedBundles` 与文档索引在同一次原子写入中保存；重复启动不再导入同一知识库。后台删除、替换或全部清空后，重启及更新镜像都不会擅自恢复。原有模型设置、管理密码、主持词和日志继续保存在原数据目录。

如需要通用空库，在首次启动前设置 `BUNDLED_KNOWLEDGE_ENABLED=false`。此开关只停用自动关联，不删除已导入的资料。需要恢复已删除主题时，可在后台从此目录重新上传对应 Markdown 文件。后续资料版本应由管理员核对后在后台维护；更新仓库不会覆盖后台已维护的知识。

Compose 自动创建和挂载持久化命名卷。改为主机目录绑定挂载时，应先确保目录可由容器内 `node` 用户（UID 1000）读写。继续使用原来的 `docker run` 命名卷时，新镜像会在同一卷上追加关联。不要使用 `docker compose down -v` 删除需要保留的数据。

## 检索与回答验证

7 份主题文件约 51.4 KiB，当前导入器生成 14 个片段，总上下文约 22,524 字符，处于 24,000 字符预算内。每次提问可得到全部主题证据，避免跨地区、旧新日期或换问法导致片段遗漏。它是当前小规模资料的实现选择，并非对任意规模知识库的最优性保证。

`npm test` 覆盖自动关联、旧索引兼容、去重、重启、删除及替换持久化、文件损坏校验，以及实际 HTTP 问答链路。58 道资料回归中，50 道检查事实证据，8 道检查“未公布、存在差异或资料不足”的边界证据是否进入上下文。HTTP 链路使用模拟模型响应，不代表真实模型的准确率、拒答质量或响应速度。

推荐使用现有“仅依据后台内容”回答模式。项目事实应保留资料时点，日期、人数、经费和名单不相互混用；访客端保持自然口语，不主动显示原文件名和来源编号。新增大量知识后可能进入排序检索模式，应再次检查覆盖情况。

## 使用前提

知识已随项目提供，不需要重新上传。已有完整模型连接配置的数据卷可直接继续问答；全新部署仍须在工作台填写自己的 API 地址、API Key 和模型名，并通过连接测试。仓库不包含真实模型凭据，不会在启动时自动发起付费模型请求。
