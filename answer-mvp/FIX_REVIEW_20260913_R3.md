## 边界

- 超时不等于服务器未执行。不能把重新读到的公开配置当作隐藏 Key 已切换或模型测试已成功的证据；也不能在未确认时自动重做替换导入。
- 保留 Demo 的登录、来源策略和现有运行配置，不新增部署前置条件。
- 前台日志队列仍有 200 条容量限制；修复的是额外误删，不是提供无限离线留存。
- 文件系统故障下，修复保证不把失败追加当作有效日志；不能承诺断电、介质损毁、多进程共享写入等未验证情形的数据绝对不丢失。
- 恢复针对当前文件的未完成尾行，不会自动修复历史上已混合成内部坏行的记录或损坏归档；本轮没有扫描、改写真实运行日志。
- 自动和浏览器测试使用临时数据、占位凭据、模拟模型/语音，不验证付费供应商或真实设备声音。

## 实现与故障验证

- 后台模型写入截止为 `max(30 秒, 模型超时 + 15 秒)`，最高 135 秒；知识导入、删除、迁移为 180 秒；状态读取/只读核对为 10 秒。截止涵盖响应头与正文，即使适配器忽略 abort 也能释放界面操作锁。未知结果保留输入，不自动重发写入；核对返回缺字段、非 JSON 或迟到时不覆盖当前有效状态。
- 日志在串行追加前检查尾部，失败时在同一文件句柄上回退至追加前的字节数；完整 JSON 仅缺换行时补齐分隔符，未完成 JSON/UTF-8 尾部才截去。真实子进程文件大小限制触发 `EFBIG`，验证 HTTP 500 → 同事件重试 200 → 重复确认，最终完整问答可查且仅一条。轮转后失败不截断旧归档。
- 前台按实际发送的 `eventId` 移除已确认事件；覆盖 201/205 次入队、成功/400 回包、503/断网重试及持久队列一致性。语音失败提示来自当前交互状态，正常下一轮清除，主持/控制中断提示优先。

### 复跑时额外修复的测试清理竞态

初次严格测试 225/225 通过，但紧接着普通测试出现 224/225：`TC-FUNC-001` 清理临时目录报 `ENOTEMPTY`，并留下测试监听进程。原因是先注册删除目录、后注册关闭服务，删除与尚未完成的日志追加发生竞态，并非问答业务断言失败。

已统一核心 HTTP 和预置知识服务测试的清理顺序：先关闭服务并等待日志，再删除自己的临时目录。新增两项确定性回归，阻塞真实 `service.stop` 日志验证关闭期间目录仍存在，以及关闭抛错也执行目录清理；修复前验证失败，修复后通过。没有通过重跑掩盖失败。

## 浏览器验收

Playwright 使用独立临时服务、随机本机端口与占位 Key。为快速故障注入，管理页测试将应用截止定时器加速至 1.5 秒；真实 10/30–135/180 秒预算由自动测试断言。

1. 模型设置：服务器实际保存成功后延迟返回，前端超时解锁；等待期间新草稿和 Key 输入保留，仅一次 PUT，晚到回包不覆盖草稿、不把结果未知改成保存成功。
2. 知识导入：实际浏览器 multipart 成功持久化后，挂起前端正文读取；截止后恢复导入按钮并保留选中文件，只读核对显示新文件，但仍保留结果未知提示，不自动重导。
3. 语音：模拟 `speak()` 同步异常，失败提示在问答结束后持续显示，发送按钮恢复；下一轮模拟 start/end 成功清除旧提示，后台分别有失败与完成日志。恢复页控制台 0 错误/警告。

最初用 `route.fetch()` 转发 multipart 的测试注入返回空文件错误，因此不作为成功导入证据；改用浏览器原生上传、仅挂起返回正文后才通过上述第 2 项。测试浏览器与临时服务均已关闭。
